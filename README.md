# InvoiceIntelligence

> A multi-tenant invoice intelligence platform on Azure: event-driven OCR ingestion, vector
> search, RAG over invoices, secured with managed identity and fully observable.

Upload invoices, extract data with Azure AI Document Intelligence, and ask questions in plain
language using RAG over tenant-isolated vector search. Built with .NET, Semantic Kernel,
Cosmos DB, Event Grid, Service Bus and Container Apps.

This repository is both an **AI-200 (Azure AI Cloud Developer Associate) certification lab**
and a **portfolio piece**. The scaffolding is in place; the implementation is built out week by
week per the plan below.

## Architecture (target)

When a tenant uploads a PDF to Blob Storage, an event-driven pipeline (Event Grid → Azure
Functions → Service Bus) runs OCR with Azure AI Document Intelligence, stores extracted fields,
and indexes the content as embeddings in a tenant-partitioned vector store. Users then ask
questions and get answers generated by Azure OpenAI, grounded in their own invoices with sources
cited. Each tenant's data is isolated at every layer: storage, cache, search and logs.

See [docs/architecture.md](docs/architecture.md) for the diagram and design decisions.

## Azure services

Container Apps · Container Registry · GitHub Actions · Cosmos DB (or PostgreSQL + pgvector) ·
Azure Cache for Redis · Azure OpenAI · Blob Storage · Event Grid · Service Bus · Azure Functions ·
Document Intelligence · Key Vault · managed identity · Entra ID · Application Insights ·
OpenTelemetry · Log Analytics.

## Solution layout

| Project | Role |
| --- | --- |
| `src/InvoiceIntelligence.Api` | Controllers, auth, RAG query endpoints |
| `src/InvoiceIntelligence.Core` | Domain, tenant context, Semantic Kernel services |
| `src/InvoiceIntelligence.Infrastructure` | SQL, vector store, Redis, Blob clients |
| `src/InvoiceIntelligence.Worker` | Service Bus consumer: chunk, embed, index |
| `src/InvoiceIntelligence.AppHost` | .NET Aspire orchestration for local dev |
| `functions/ingest_trigger` | Azure Function (isolated worker): Blob/Event Grid → Document Intelligence → Service Bus |
| `infra/main.bicep` | All Azure resources, one command to deploy |
| `tests/` | Test projects |
| `.github/workflows/` | Build, test, push image, deploy |

## Build

```bash
dotnet build
```

Run locally via Aspire:

```bash
dotnet run --project src/InvoiceIntelligence.AppHost
```

## 8-week build and study plan

| Week | Build | Study (AI-200 area) |
| --- | --- | --- |
| 1 | Dockerfiles, Container Registry, deploy API to Container Apps, GitHub Actions pipeline | Containerized solutions |
| 2 | Worker as a second container app, Bicep for all resources so far | Containerized solutions |
| 3 | Move embeddings and vector search to Cosmos DB or pgvector, tenant-partitioned | Data services |
| 4 | Redis cache for repeated queries and embeddings, hybrid search tuning | Data services |
| 5 | Azure Function: Blob upload triggers Document Intelligence → Service Bus → Worker indexes | Connect to and consume services |
| 6 | Key Vault, managed identity everywhere, Entra ID auth on the API, App Insights via OpenTelemetry | Secure, monitor, troubleshoot |

| 8 | Official practice assessment, fix weak spots, book the exam | All areas |
